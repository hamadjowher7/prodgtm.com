# ProdGTM Website Plan

## Summary

Create a premium one-page website for `prodgtm.com` that positions ProdGTM as a 16-member AI-native product and growth studio: 2 humans and 14 agents building its own portfolio of micro apps and internet businesses.

The site should make one thing unmistakably clear: ProdGTM does not do client services, turnkey delivery, agency work, or outsourced product builds. Every product, app, and business is fully owned, operated, and grown by ProdGTM.

Primary CTA: a brief contact/calendar link for founder, investor, distribution, partnership, or strategic conversations.

The first public version should include three upcoming products: TuitionMasterPro, CollectHero, and DentistPro.

AI should be central to the positioning: ProdGTM's 14 AI agents build and market micro apps by researching markets, prototyping products, creating content, distributing campaigns, and summarizing learnings.

## Core Positioning

### One-line positioning

ProdGTM is a 16-member AI-native studio: 2 humans and 14 agents building and marketing fully owned micro apps.

### Supporting message

We identify sharp market gaps, use AI agents to build focused software products, launch quickly, and compound growth through content, distribution, experimentation, and operating discipline.

### Important boundary

We are not an agency. We do not build turnkey products for clients. We do not take outsourced product briefs. We only build, own, and grow our own products.

## Audience

The website should speak to:

- Strategic partners who may help with distribution, data, expertise, or deal flow.
- Potential collaborators who understand product, engineering, growth, design, or operations.
- Investors or acquirers interested in owned software assets.
- Curious visitors who need to quickly understand what ProdGTM is and is not.

The site should not optimize for:

- Client lead generation.
- Service package inquiries.
- RFPs, freelance requests, or agency-style retainers.

## Tone

Use a confident, concise, premium tone.

The language should feel:

- Sharp, modern, and editorial.
- Founder-led rather than corporate.
- Selective and independent.
- Clear about ownership and non-agency positioning.
- Explicitly AI-native without sounding like a generic automation agency.

Avoid language that sounds like:

- A generic SaaS agency.
- A growth consultancy.
- A venture studio that takes external client briefs.
- A startup incubator accepting open applications.

## Visual Direction

### Overall feel

The site should feel premium, precise, and product-native.

Recommended style:

- Dark or near-black base with restrained contrast.
- Crisp typography with large hero type.
- Subtle motion or interactive visual detail.
- Fine borders, glass-like panels, grid lines, or interface-inspired surfaces.
- One or two accent colors only, used sparingly.

Avoid:

- Purple-blue gradient-heavy startup template look.
- Generic agency sections like testimonials, services, case studies, and pricing.
- Overly decorative cards with vague buzzwords.
- Stock imagery or fake team photos.

### Suggested palette

- Background: near black, charcoal, or deep graphite.
- Text: warm white / soft gray.
- Accent: electric green, signal blue, or amber used very sparingly.
- Lines: low-opacity white or cool gray.

### Logo Direction

Use the included `prodgtm-logo.svg` as the starting logo asset.

Concept:

- Text-only wordmark: `ProdGTM`.
- `Prod` should use the primary light text color.
- `GTM` should use the green accent color.
- No icon, tagline, product blocks, or arrow inside the logo.

Recommended usage:

- Use the full horizontal logo in the site header.
- Use the square icon mark as the favicon/social avatar base.
- Keep the logo monochrome or near-monochrome on dark backgrounds; use the accent only inside the mark.

Logo personality:

- Product-native.
- Precise.
- Independent.
- Not agency-like, playful, or overly corporate.

### Typography

Recommended approach:

- Use a clean modern sans for most text.
- Use a sharper display style for the hero if available.
- Keep copy minimal with strong spacing.

## Implementation Recommendation

Build as a static one-page website and deploy through GitHub Pages.

Recommended stack:

- Plain HTML, CSS, and JS for the current version.
- GitHub Pages branch deployment from the repository root.
- `CNAME` file set to `prodgtm.com`.
- `.nojekyll` file to disable Jekyll processing.
- DNS pointed to GitHub Pages, with HTTPS enforced once available.

The first version does not need a CMS, backend, blog, login, newsletter, analytics dashboard, build step, or server runtime.

Detailed deployment instructions live in `github-pages-deployment.md`.
